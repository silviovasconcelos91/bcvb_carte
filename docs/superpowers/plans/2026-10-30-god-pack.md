# God pack — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un booster peut être un « god pack » (toutes ses cartes dans les raretés éligibles), par hasard (1 sur N réglable) ou par code ; l'ouverture d'un god pack a une animation dorée dédiée.

**Architecture:** Quatre colonnes en base (`game_settings.god_pack_odds`, `rarities.in_god_pack`, `booster_codes.god_pack`, `booster_openings.god_pack`). `open_booster` décide du god pack avant le tirage et passe un drapeau à `private.draw_card`. Chaque élément renvoyé gagne `god_pack: boolean` ; `Reveal` en déduit l'animation. Le client local (mode démo de `src/api/game.ts` et `src/api/admin.ts`) reproduit les mêmes règles.

**Tech Stack:** React 19 + TypeScript 5.9 + Vite 8, Supabase (Postgres plpgsql), CSS maison (`src/styles/base.css`).

**Spec:** `docs/superpowers/specs/2026-10-30-god-pack-design.md`

## Global Constraints

- **Aucun lanceur de tests** dans le projet, le plan n'en ajoute pas. Vérification : `npx tsc --noEmit`, `npm run build`, requêtes SQL dans Supabase > SQL Editor, parcours manuels en mode démo (`npm run dev`) et sur `/demo`.
- Tout changement SQL va **à la fois** dans `supabase/schema.sql` (aux endroits existants : tables, `draw_card`, `open_booster`, seed des raretés) et dans le patch rejouable `supabase/patches/2026-10-30-god-pack.sql`, avec l'en-tête habituel des patches (voir `2026-10-25-choix-serie-booster.sql`).
- `god_pack_odds` : entier ≥ 0, **0 = désactivé, valeur par défaut 0**. Probabilité = 1 / N.
- Raretés éligibles par défaut : codes `ultra_rare`, `legendary`, `secret`.
- Un code « carte précise » (`card_id`) ne donne **jamais** de god pack et ne peut pas avoir `god_pack = true`.
- Message d'erreur exact (code god pack sans carte éligible) : « Aucune carte disponible pour un god pack dans cette série ».
- **Aucun texte ni badge « GOD PACK » à l'écran du joueur.** Hors god pack, l'animation reste strictement identique à aujourd'hui.
- Nouveaux champs TS optionnels (`?`), comme `gems`/`free_booster_max`, pour tolérer une base pas encore patchée.
- Textes en français, ton « tu » côté jeu. Commentaires en français, densité du code voisin.

## Review Focus

1. **Code god pack sur une série sans carte éligible** : erreur exacte, code **non consommé** (`uses_count` inchangé, pas de ligne dans `booster_code_redemptions`). *Tâche 1, étape 4.*
2. **Chance active, série choisie sans carte éligible** : booster normal, aucune erreur, `god_pack = false`. *Tâche 1, étape 4 et tâche 2, étape 3.*
3. **Rareté éligible de poids 0** : ne tombe jamais dans un god pack. *Tâche 1, étape 4.*
4. **Booster normal contenant une Ultra rare** : animation de paquet inchangée (halo de la meilleure carte, durée habituelle), pas de dorure. *Tâche 4, étape 4.*
5. **Code « carte précise » quand la chance vaut 1 (100 %)** : une seule carte, `god_pack = false`. *Tâche 1, étape 4.*

  - `god_pack_odds = 1` + code « carte précise » → 1 carte, `god_pack: false` ;
